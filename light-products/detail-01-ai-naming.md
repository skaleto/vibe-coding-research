## A. 完整 Prompt v1（拿来即用）

### A.1 宝宝起名 Prompt 完整字符串

#### A.1.1 System Prompt

```
你是一位精通《诗经》《楚辞》《唐诗三百首》《宋词三百首》《论语》《周易》《说文解字》的国学起名顾问，过去 20 年帮 5000+ 家庭起过名字。你的风格特点：

【知识储备】
- 熟稔《诗经》305 篇、《楚辞》《九歌》《九章》全集、《论语》20 篇、唐宋八大家代表作
- 能在 3 秒内回忆任意经典原句的上下文与字义
- 熟悉《通用规范汉字表》一二级字（共 6500 字），坚决不用三级字（生僻字）和不收录字
- 了解《中华人民共和国国家通用语言文字法》第十七条对人名用字的规范要求

【起名原则】
1. 必须真实出处：每个名字的「出处」字段必须能在《古文观止》《全唐诗》《诗经》等公开经典中查到，不允许编造典故、不允许只写"古诗云"
2. 字义吉祥：避开「殇/亡/孤/煞/凶/丧/哀」等悲苦字
3. 字形美观：偏旁不重复（如「林森」全是木）、笔画不极端（每个字 5-15 画为宜）
4. 音律和谐：声调避免三字全同调（如全是去声）；姓+名末字声调对比
5. 男女差异：女宝侧重「灵/婉/清/慧/雅/宁/瑶/汐/苒」类柔美字；男宝侧重「沐/朗/承/澈/砚/铮/竹/淮」类清朗字；中性字可用「禾/夕/予/安/允/林」
6. 严控网红名黑名单（见下）

【输出风格】
- 释义文字 150-220 字，温和、有文化感、不玄学、不算命、不预测运势
- 不使用「五行/八字/吉凶/打分/天格/地格/人格」等命理词汇
- 用「字义」「典故」「期许」三段式：第一段讲单字含义，第二段讲出处与典故背景，第三段表达对宝宝的性格期许
```

### A.3 生僻字过滤规则

#### A.3.1 一二级字符集白名单

**实现方式**：
1. 下载《通用规范汉字表》一二级字（共 6500 字）：可用 `pypinyin` + 内置字典 / 或自行准备 JSON
2. 后端拿到 LLM 输出后，逐字校验：

```python
COMMON_CHARS = set(open("gb2312_level1_level2.txt").read())  # 6763 字

def is_valid_name(given_name: str) -> tuple[bool, str]:
    for ch in given_name:
        if ch not in COMMON_CHARS:
            return False, f"生僻字: {ch}"
    return True, "ok"
```

```python
HARD_BLACKLIST = {"梓涵", "紫萱", "子轩", "子涵", "梓萱", "沐宸", "沐辰", "雨桐", "欣怡", "可馨", "思琪", "雨涵", "梓睿", "俊宇", "浩然", "浩宇", "子墨", "嘉怡", "婉清"}
SOFT_BLACKLIST_CHARS = {"梓", "萱", "涵", "轩", "宸", "桐", "怡", "馨", "琪", "睿", "宇", "然", "墨"}

def filter_results(names: list) -> list:
    # 硬黑名单：直接剔除
    filtered = [n for n in names if n["given_name"] not in HARD_BLACKLIST]
    # 软黑名单：所有名字中含 SOFT_BLACKLIST_CHARS 的总数不超过 1 个
    soft_count = 0
    final = []
    for n in filtered:
        has_soft = any(c in SOFT_BLACKLIST_CHARS for c in n["given_name"])
        if has_soft and soft_count >= 1:
            continue
        if has_soft:
            soft_count += 1
        final.append(n)
    return final
```

#### A.3.3 同音字处理

**规则**：
1. 同声母韵母（不含声调）的字组合视为同音 → 一组中只能保留一个
2. 姓 + 名末字声调不能全为去声（4-4）或全为阴平（1-1）—— 防止"读着别扭"
3. 检查谐音：维护一份 50 字小黑名单（霉/姨/驴/吴/吴/狗 等谐音不雅字）

```python
HOMOPHONE_BAD = {"梅": "霉", "姨": "姨母", "吴": "无", "史": "屎"}  # 例
def check_homophone(full_name: str) -> bool:
    return not any(c in HOMOPHONE_BAD for c in full_name)
```

#### A.3.4 极端笔画过滤

- 单字笔画 < 4 或 > 18 直接剔除（如「乙」「鼇」）
- 名字总笔画 > 40 视为过繁

| 付费转化率 | payment_success / input_submit | 8-15% |
| 客单价 | sum(amount) / payment_success | ¥50-80 |
| 重新生成率 | regenerate / input_submit | <20%（低则说明 prompt 质量好）|
| 海报生成率 | poster_save / result_view | 40%+ |
| 分享率 | poster_share / poster_save | 30%+ |
| D1/D7 留存 | 次日/7 日内重新打开率 | 30% / 15% |
| 退款率 | refund / payment_success | <5% |
| LLM 失败率 | llm_fail / loading_start | <3% |

### F.5 工具选型

**推荐组合**：

**国内主战场**（iOS 国区 + 应用宝 + 华为）：
- **友盟 U-App**：免费、合规、含基本漏斗 / 留存 / 渠道分析。每日 DAU 自动统计。
- **自建埋点 BFF**：用 Cloudflare Workers + D1 存关键事件，每天定时聚合到一张 Grafana 看板。

**海外双发**（未来）：
- **Firebase Analytics**：免费、好用、Google Sheets 自动报表

**第一阶段（M1）**：
- 友盟 + 1 张极简自建看板（Cloudflare D1 + Notion 嵌入 chart）足够

**不推荐**：神策 / 火山引擎（贵且重，对个人开发者过载）

### G.4 名字去重缓存策略

**目标**：同一用户在同一组输入下重复生成时，部分相同候选不刷新；不同用户独立。

#### 方案：Redis + 用户级缓存

```python
# 缓存键：user_id + 输入特征 hash
def get_cache_key(user_id: str, inputs: dict) -> str:
    input_hash = hashlib.md5(
        json.dumps(inputs, sort_keys=True).encode()
    ).hexdigest()
    return f"naming:{user_id}:{input_hash}"

async def get_names_with_cache(user_id, inputs, force_refresh=False):
    cache_key = get_cache_key(user_id, inputs)
    if not force_refresh:
        cached = await redis.get(cache_key)
        if cached:
            return json.loads(cached)

    # LLM 生成
    names = await generate_names(**inputs, user_id=user_id)

    # 全局去重（防止同一句生成同名）
    existing = await redis.smembers(f"global_names:{inputs['surname']}")
    names = [n for n in names if n["full_name"] not in existing]

    # 不够 10 个则补充
    while len(names) < 10:
        more = await generate_names(**inputs, user_id=user_id, exclude=names)
        names.extend(more)
        names = names[:10]

    # 写入缓存
    await redis.setex(cache_key, 86400 * 7, json.dumps(names))  # 7 天有效
    await redis.sadd(f"global_names:{inputs['surname']}", *[n["full_name"] for n in names])
    return names
```

**轻量方案（无 Redis）**：用 Cloudflare D1（SQLite）+ 2 张表：
- `cached_results` (user_id, input_hash, names_json, created_at)
- `global_names` (surname, full_name)

### G.5 数据可信度抽样测试方案

**问题**：LLM 可能编造典故（如"《诗经·小雅·节南山》'知微知章'"实际不存在）。

**抽样测试**：

#### 方案 1：定期人工抽检（M1-M2）
- 每天从 LLM 返回中随机抽 50 个名字
- 人工用《古诗文网》《诗经在线》查证 `original_quote` 是否真实
- 误检率超 5% 触发 prompt 重新优化

#### 方案 2：自动化校验（MVP 必须有）
- 维护一个**典故白名单数据库**（典籍 + 章节 + 原文逐字索引）
- 每个生成的名字调用 `verify_quote(book, chapter, quote)` 校验
- 只有校验通过的名字才能返回给用户；校验失败的候选直接丢弃并触发重试
- MVP 至少覆盖诗经、楚辞核心篇目、唐诗 300 首、论语；未入库典籍不得作为出处展示

**初始数据库构建（上线前完成）**：
- 诗经 305 篇 + 楚辞 + 唐诗 300 首 + 论语 20 章
- 使用公版/可授权文本来源清洗，保留来源版本号；避免未经许可批量复制商业站点内容
- 存为 SQLite 全文索引（FTS5）

```python
import sqlite3
conn = sqlite3.connect("ancient_quotes.db")
conn.execute("CREATE VIRTUAL TABLE quotes USING fts5(book, chapter, text)")

def verify_quote(book: str, chapter: str, quote: str) -> bool:
    rows = conn.execute(
        "SELECT * FROM quotes WHERE book MATCH ? AND chapter MATCH ? AND text MATCH ?",
        (book, chapter, quote)
    ).fetchall()
    return len(rows) > 0
```
