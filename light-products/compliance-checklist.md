# 合规验收清单（5 个产品 · Codex Review 加固版）

**版本**：v1.0 / 2026-05-28
**适用**：本目录下 5 个产品 detail 文档的上架前验收
**口径**：每个产品上架（提审）**前必须**逐项核验，未通过项一律不上架
**复审周期**：每月 1 次（关键热线/法规变化时立即触发）

---

## 通用底层（5 个产品全部适用）

### 资质与备案
- [ ] iOS 国区 Apple Developer 个人/企业账号已激活（含 D-U-N-S 编码）
- [ ] 应用宝 / 华为 / 小米 / OPPO / vivo 开发者账号已注册（至少应用宝）
- [ ] 工信部 ICP 备案 + 公安部网络安全备案
- [ ] 主体（个人/工作室/公司）已确认承担连带责任能力
- [ ] **不上微信小程序**（除非 idea 明确不踩"算命/医疗/教育"红线）

### 法律文本
- [ ] 《用户协议》《隐私政策》齐全，含"AI 生成内容免责声明"
- [ ] 内含明确的退款政策（参照 Apple / 应用宝标准）
- [ ] 商标查询：App 名称未被注册（中国商标网 + 国家知识产权局）
- [ ] LLM 服务商合规：DeepSeek / 智谱 / 通义有合规白名单；OpenAI 在国内备案受限，谨慎使用

### AI 标识（《互联网信息服务深度合成管理规定》第 17 条）
- [ ] 所有 AI 生成内容**显著标识** "AI 生成"
- [ ] AI 不可自称"我不是 AI / 我是真人"（Prompt system 禁止）
- [ ] 后台留存 AI 生成日志 ≥ 6 个月（含 user_id / prompt / output / timestamp）

## 1️⃣ AI 起名（detail-01）

### 🔴 核心雷点：LLM 编造典故出处 → 消法欺诈 + 退一赔三

### A. 典故校验（MVP 硬门槛）
- [ ] **典故白名单数据库已构建**：诗经 305 篇 + 楚辞核心 + 唐诗 300 首 + 论语 20 章
- [ ] **数据库来源合规**：用公版/可授权文本（中国哲学书电子化计划 https://ctext.org、ZDIC 等），不爬古诗文网/诗源网商业整理本
- [ ] **数据库保留版本号**：典籍名 + 章节 + 原文 + 来源 URL + 入库日期
- [ ] `verify_quote(book, chapter, quote)` 函数 100% 覆盖每个候选名
- [ ] 校验失败的名字**直接丢弃并触发重试**，不进展示/海报/付费报告
- [ ] **上架前人工抽检 50 条付费结果**，误检率 < 2% 才放行
- [ ] 每日抽检 30 条付费结果，误检率超 2% 暂停投放并回滚 prompt

### B. 内容合规
- [ ] System prompt 禁止 LLM 推荐"五行/八字/命理/吉凶/姻缘"
- [ ] 网红名 19 字硬黑名单 + 13 字软黑名单已实现
- [ ] 生僻字过滤（一二级字符集白名单）
- [ ] App 介绍页 lint：禁词清单（八字算命、命理预测、吉凶、姻缘、阴阳五行）

### C. 类目与渠道
- [ ] iOS 国区类目：参考 / 生活
- [ ] **不上微信小程序**（"算命八字"红线）
- [ ] 应用宝类目：生活
- [ ] 安卓商店避开"占卜"标签

### D. 用户保护
- [ ] 付费墙明确"30 天无理由退款"
- [ ] 客服邮箱 / 微信留 24h 响应
- [ ] 每次结果展示"AI 生成仅供参考，请家庭长辈复核"

## 2️⃣ AI 倒数日 Pro（detail-02）

### 🟢 无显著法律雷点 — 唯一干净的 idea

### A. 上架基础
- [ ] iOS 国区类目：效率 / 生活
- [ ] 应用宝类目：实用工具
- [ ] WidgetKit 5 尺寸（systemSmall/Medium/Large + accessoryCircular + accessoryRectangular）全部支持
- [ ] App Group 数据同步无 race condition
- [ ] iCloud 同步在弱网/离线/冲突场景下数据无丢失（必测）

### B. IAP 与定价
- [ ] 付费墙符合 App Store IAP 规范（**不引导外部支付**）
- [ ] 5 套主题购买流程顺畅，无"假免费真付费"陷阱
- [ ] 续费/退订路径明显
- [ ] 应用宝支付链路独立测试

### C. 用户数据
- [ ] 隐私政策列明数据收集类型（仅纪念日文字 + 本地图片可选）
- [ ] 不上传任何 PII 到云端（除非用户主动开启 iCloud 同步）
- [ ] 删除账户路径在 App 内 1 步可达

### D. 主题素材版权
- [ ] 5 套主题的配色/字体/装饰元素全部使用授权或公版资源
- [ ] 字体：思源宇/思源黑体（开源），系统字体（免费），不用未授权商业字体
- [ ] 装饰 emoji 不用第三方 emoji 包

## 3️⃣ AI 植物医生（detail-03）

### 🔴 核心雷点：推荐农药剂量 → 农药经营违规 + 食品安全连带责任

### A. 内容禁区（Codex Review 强制）
- [ ] System prompt **禁止输出**：
  - 任何农药商品名（绿亨一号 / 施克粉 / 敌百虫粉剂等）
  - 任何农药通用名（多菌灵 / 波尔多液 / 吡虫啉 / 代森锰锌等）
  - 任何剂量或稀释比例（1:1000 / 5ml/L / 喷洒频次）
  - 任何替代性民间偏方
- [ ] System prompt **只允许输出**：
  - 非药物养护：隔离、剪除病叶、销毁病果、改善通风、调整光照、控水、换土、清洁工具
  - 安全提醒：食用作物处理 + 孕妇/婴幼儿/宠物注意
  - 咨询建议："请带照片咨询本地花卉店 / 园艺师 / 农资人员"

### B. 概率与免责
- [ ] 输出 schema 改为 `likelihood: "高/中/低"`，**不使用百分比**
- [ ] 输出 schema 改为 `recovery_outlook: "高/中/低"`，**不使用百分比**
- [ ] 每次输出含 disclaimer："本诊断由 AI 基于图像生成，仅供家庭园艺参考"
- [ ] AI 拟人化禁止（不允许"15 年资深植物病理学家"）

### C. 测试回归
- [ ] 10 个测试用例（多肉黑腐 / 绿萝叶黄 / 番茄早疫 / 月季白粉 / 仙人掌徒长 / 文竹枯黄 / 君子兰夹箭 / 兰花软腐 / 龟背竹烂根 / 草莓灰霉）全部回归通过
- [ ] 食用作物（番茄/草莓/辣椒）路径**双重 lint**：不含药剂、含"咨询农资"提示
- [ ] 违禁植物（大麻/罂粟）拒诊断 + 提示"建议咨询专业人士"
- [ ] 非植物图片（人脸/天空/动物）拒诊断

### D. App 描述与类目
- [ ] App 介绍页禁词：治病 / 药 / 处方 / 包治 / 神药
- [ ] iOS 类目：生活方式 / 参考
- [ ] 应用宝类目：生活
- [ ] 截图文案不出现具体药剂名

### E. 用户教育
- [ ] 首页/结果页 banner："我们不开药方，只给养护建议"
- [ ] 严重病害自动跳转"建议咨询本地园艺/农资人员"

## 4️⃣ AI 梦境日记（detail-04）

### 🔴 核心雷点：硬编码停用热线 → 危机干预失败 → 人身安全责任

### A. 危机热线管理（Codex Review 强制）
- [ ] **热线全部存远端配置**（不硬编码到代码/PRD/Prompt）
- [ ] 每条热线记录必含：名称 + 号码 + 服务地区 + 服务时间 + 来源 URL + **最后核验日期** + **核验人**
- [ ] **每月 1 号人工复核全部热线**（上线前先核一遍）
- [ ] **配置缺失 fallback**：显示"请联系本地紧急电话/可信任的人/专业心理机构"通用文案，**不编造号码**
- [ ] 海外 locale 路由：en-US / en-GB / en-AU / en-CA 各自配置，可优先使用 IASP 资源目录
- [ ] **不依赖 LLM 自觉**，客户端强制注入 disclaimer + 热线
- [ ] 国内热线参考来源：国家卫生健康委员会官方公布、地方政府卫健委、各大三甲医院心理科官网

### B. 严重情绪三级检测
- [ ] **一级触发**（自杀/自残/跳楼/上吊/割腕等关键词）：
  - 暂停常规梦境分析
  - 只输出关怀回应 + 求助入口
  - **删除"我现在还好，继续分析"按钮**（不允许绕过危机干预）
  - 按钮：「打开拨号」「发送给信任的人」「稍后再记录」
  - 后台告警 + 隐私保护下记录触发标记
- [ ] **二级触发**（绝望/痛苦/熬不下去）：常规分析 + 末尾追加暖色卡片 + 热线
- [ ] **三级触发**（孤独/累/想消失）：常规分析 + 末尾温和建议
- [ ] 三级关键词系统每月复核（含网络新词如"emo"、"破防"等）
- [ ] False Positive 处理：触发后允许用户标注"误报"，反馈到关键词优化

### C. 合规话术（DUMP TO LINT）
- [ ] App 名称禁词：解梦 / 算命 / 占卜 / 测命 / 运势 / 吉凶
- [ ] App 介绍禁词同上 + 预测 / 命理 / 灵性 / 阴阳
- [ ] 截图文案禁词同上
- [ ] App 描述禁词同上
- [ ] 安全替代词：梦境日记 / 梦境记录 / 睡眠日记 / 心理日记 / 潜意识 / 自我探索

### D. 类目与上架
- [ ] iOS 国区类目：**健康健身（不选"心理咨询"，选"健康记录"或"生活记录"）**
- [ ] 不上微信小程序（迷信类红线）
- [ ] 上架前用最小包做合规预审，被拒立即回滚走 4.3(b) 申诉
- [ ] AI 标识在每次输出顶部
- [ ] 反沉迷弹窗：连续 7 天/天 30 次记录梦境自动触发休息提示

### E. 海外双发（如启用）
- [ ] App Store 海外区使用 Jung/Freud/Gestalt 多流派术语合规
- [ ] 不在 Health & Fitness 类目下声称"治疗 anxiety / depression"
- [ ] EU 区 GDPR：用户数据导出/删除路径

## 5️⃣ 宠物心情卡片（detail-05，原"猜狗翻译器"）

### 🔴 核心雷点："翻译"措辞 → 虚假宣传 → 消法争议

### A. 产品定位（绝对原则）
- [ ] App 名称**不含"翻译"二字**：使用"宠物心情卡片"/"萌宠对白生成器"/"喵语日记"等
- [ ] App 介绍页**置顶**"⚠️ 仅供娱乐，AI 生成宠物心情卡片，非真实翻译动物语言"
- [ ] App Store 截图不出现"翻译准确率""真实翻译"等承诺
- [ ] 类目选择：**娱乐 / 参考**（不选"工具""教育"）

### B. AI 输出合规
- [ ] System prompt 强制输出 `disclaimer` 字段："⚠️ 仅供娱乐，AI 生成宠物心情卡片"
- [ ] Disclaimer 客户端强制嵌入卡片底部，不可隐藏/不可删除
- [ ] Prompt 禁止 LLM 输出"准确率""译文精度""真实意图"等表达
- [ ] Prompt 禁止严肃宠物行为学诊断（如"你的猫可能有焦虑症"）

### C. 卡片素材
- [ ] 3 套海报模板的水印/二维码不可移除（免费版固定，付费版可选透明）
- [ ] Disclaimer 在所有海报底部以可读字号呈现（不能用 1pt 字号糊弄）
- [ ] 不使用任何明星宠物/网红宠物素材

### D. 用户保护
- [ ] App Store / 应用宝 退款政策友好（不超过 7 天无理由）
- [ ] 客服明确告知"娱乐用途，不退款理由不成立"
- [ ] 差评应对 SOP：用户投诉"假的"统一回复"⚠️ 仅供娱乐，我们已在介绍页声明"

### E. LLM 与成本
- [ ] 选用低成本文本模型（DeepSeek / 智谱 GLM-4-Flash），单次 ¥0.005 以内
- [ ] 月度成本上限 monitor，超 ¥500/月自动降级
- [ ] **不与单一模型版本号绑定**（避免模型升级后成本暴涨）

## 通用上架前 24 小时 final checklist

无论哪个产品，提审前 24 小时跑一遍：

- [ ] 全部测试用例回归通过
- [ ] 监控告警接好（崩溃/异常/API 错误率）
- [ ] 付费链路真实下单测试至少 3 次
- [ ] 退款链路真实操作至少 1 次
- [ ] 客服邮箱/微信测试可达，72h 内有响应预案
- [ ] 隐私政策 / 用户协议 链接可访问且非测试域名
- [ ] App Store 截图最后一遍人工审核（不含禁词、不含未授权素材）
- [ ] 备用 prompt（被审核拒后立即可用）已准备 2-3 套
- [ ] **AI 生成日志已能 6 个月留存**（监管要求）

## 复审与持续合规

| 频次 | 项目 |
|---|---|
| **每周** | 用户投诉/差评 review、关键词 lint 复检 |
| **每月** | 心理热线全部核验、合规禁词清单更新、AI 抽检（起名典故、植物诊断、梦境分析）|

## 出问题怎么办（事故响应预案）

### 被 App Store / 应用宝拒审
1. 30 分钟内：判断是否触碰 codex review 的雷点之一
2. 2 小时内：回滚到上一个通过审核的版本（保留代码 + 数据隔离）
3. 24 小时内：提交申诉（参考 detail-04 § D.5 / D.6 模板）

### 用户投诉/媒体曝光
1. 1 小时内：暂停付费投放
2. 4 小时内：客服全员同口径回复
3. 24 小时内：版本灰度回滚 + 内部复盘

### 法律风险预警
1. 收到律师函/工信部约谈/消法投诉时：**当日下架**，不犹豫
2. 委托律师 review，对方诉求合理的话快速整改
3. 不要尝试"硬刚"——个人开发者打不起官司
